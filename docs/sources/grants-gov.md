# Grants.gov research funding — Phase 05 Checkpoint C

Reviewed 2026-10-29 after A/B closed. Small nonpersonal technical subset; researcher institution, country, career stage and discipline are unknown.

## Fit and permission

Owner: HHS Grants.gov, official federal portal. [Guide](https://www.grants.gov/api/api-guide), [search2](https://www.grants.gov/api/common/search2) and [fetchOpportunity](https://www.grants.gov/api/common/fetchopportunity) document unauthenticated reads. [Terms](https://www.grants.gov/api/terms-conditions) permit search/display/analysis/retrieval, require attribution/accurate representation and permit limits/termination without SLA. No quantitative quota found; use conservative bounds/backoff. A direct bounded request for `api.grants.gov/robots.txt` returned 403, so no robots directives were established. Approval rests on the expressly documented API access/terms, not a claim that robots permits crawling. No bypass or arbitrary site crawl. Do not repeat insecure curl TLS examples. No API key, application submission or grantor API.

Required attribution, shown in this repository/CLI and required in future Telegram source views:

> This product uses the Grants.gov API but is not endorsed or certified by the U.S. Department of Health and Human Services.

Fixed scope: NSF, explicit ST (Science/Technology/other R&D), keyword research, one latest result per instrument G/CA. Current candidates: 363764 / 20-558 engineering-formation research grant; 363481 / 26-513 AI infrastructure cooperative agreement. The latter restricts lead institutions to US research/nonprofit organisations and US-campus IHEs; the former has engineering faculty PI restrictions. Neither proves personal eligibility. These genuine research calls are useful through an eligible host; this is not a broad catalogue represented as eligible individual awards. Confirm actual host/subject fit before personalized notifications. No profile is invented.

NIH was evaluated: documented API works, but latest health examples select a biomedical discipline without user evidence and some eligibility fields refer to full announcements. Not selected. UKRI offers RSS and fellowship/grant types but sampled paths require UK-organisation eligibility, adding no alignment advantage. No second funding adapter is needed if these instrument paths pass.

## Classification and dates

[Official definitions](https://www.grants.gov/learn-grants/grant-terminology) distinguish Grant from Cooperative Agreement by substantial agency involvement. G → `grant`; CA-only research support → `research_funding`. Both instruments on one record remain one grant, preserving both. PC/O need additional review and are excluded. This applies PRODUCT_SPEC's existing no-duplicate rule.

Portal ID + opportunity number identify announcement/cycle. New portal ID with reused number/homepage remains separate conservatively. Versions/deadlines are mutable evidence. A continuing multi-year solicitation remains one announcement; do not invent annual subcalls from changing dates.

Posted → open; closed/archived → closed with original status retained; a newly discovered forecasted call → unknown lifecycle + explicit forecast attribute/estimated-deadline label. Canonical lifecycle retains stronger known evidence under existing reconciliation; if an already-open announcement later reverts to forecast, its latest `attributes.funding.source_status`/estimated label must take precedence over the retained coarse lifecycle when future views decide whether applications are currently accepted. This is a source-status projection requirement for Phases 07-09, not an invented open state or a changed lifecycle enum. Portal `*-00-00-00` fields are calendar dates, not midnight UTC evidence. Keep closing date date-only/zone unknown; store publication date in attributes, published_at null without an instant. Preserve applicant types/categories and bounded additional eligibility; funder country is not research location.

## Work bounds and evidence

Exact HTTPS endpoints `https://api.grants.gov/v1/api/search2`, `https://api.grants.gov/v1/api/fetchOpportunity`; read-only JSON POST ([ADR 0011](../adr/0011-bounded-read-only-json-post.md)). Two searches rows=1 and at most two details; no unbounded pagination/enrichment. Explicitly partial latest-call scope, retaining hit counts. One page/task; shared 15-second deadline; 128 KiB/search, 256 KiB/detail, 4 KiB requests. Discard response tokens, contacts and attachments outside needed factual fields. No redirects/external announcement fetching; daily cadence proposed, no automation.

At 2026-10-29 14:23Z the actual approved path read 1,736 + 23,577 + 1,600 + 31,767 decoded bytes (58,680 total), 3.26 seconds collection; 4,203-byte sanitized projection mapped two records in 6.75 ms, local RSS proxy 60.4 MB. Search totals 113 G / four CA demonstrate deliberately partial scope. No pagination or complete-catalogue claim. JSON parse+projection and mapping upper-bound benchmarks are separately recorded in the phase report. A real HHS forecast was inspected only to confirm `estApplicationResponseDateStr` and other forecast fields; it is outside enabled NSF/ST scope and is a declared schema/negative fixture.

Fixtures pin selected public factual API fields from NSF 363764 / 20-558 and 363481 / 26-513, accessed 2026-10-29, in `tests/fixtures/grantsgov/manifest.json`. They exclude tokens, grantor contacts, attachments and full proposal prose. SHA-256 covers canonical serialization of LF-normalized fixture strings using the domain digest function. Synthetic status/date/amendment/cycle variants are labeled; the API has no immutable dataset commit, so observed document versions/revisions are metadata, not identity.

Manual official checks: [NSF PFE: RIEF](https://www.nsf.gov/funding/opportunities/pfe-rief-pfe-research-initiation-engineering-formation) and its [20-558 solicitation](https://www.nsf.gov/funding/opportunities/pfe-rief-pfe-research-initiation-engineering-formation/nsf20-558/solicitation) agree on title, grant instrument, 10 November 2026 and engineering-faculty restrictions.
