# OpenReview scoped conference-call source — Checkpoint C

Reviewed 2026-10-29 after Checkpoints A/B closed. The CCFDDL paths cover events/workshops and their paper deadlines, but contain no distinct workshop-organizer call. The phase contract also requires a configured path for genuine standalone calls. A second provider is justified for this specific gap; no venue search, article collection or general OpenReview crawler is added.

## Permission, interface and evidence

[OpenReview API documentation](https://docs.openreview.net/getting-started/using-the-api) identifies API 2 as current. The [official client](https://github.com/openreview/openreview-py/blob/master/openreview/api/client.py) documents GET invitations by ID and `expired`/`limit` filters. No Python code/client is installed or copied. [Terms dated 2024-09-24](https://openreview.net/legal/terms) provide public API access according to readership permissions, CC0 metadata, and CC BY 4.0 configuration records. Only minimal public invitation metadata is retained, with source attribution; no articles, profiles, contacts, reviewer information or workflow code. This small metadata use supports scientific event coordination. API robots returned `User-agent: *` with only email-query paths disallowed; this source uses ID queries, no email or authentication. No rate SLA was found: one bounded request/run, proposed daily cadence, respect 429/Retry-After and existing bounded retry/cooldown. Do not expand to private groups or authenticated requests.

The official [ICLR 2027 workshop call](https://iclr.cc/Conferences/2027/CallForWorkshops) links to `ICLR.cc/2027/Workshop_Proposals`. A public bounded group inspection (9,538 bytes) returned its exact `submission_id`: `ICLR.cc/2027/Workshop_Proposals/-/Submission`. This is a distinct call to propose/organize workshops, not a duplicate ICLR research-paper event.

Exact approved ingestion endpoint: `https://api2.openreview.net/invitations?id=ICLR.cc%2F2027%2FWorkshop_Proposals%2F-%2FSubmission&expired=true&limit=1`. Public inspection returned HTTP 200, JSON, 4,850 decoded UTF-8 bytes, one invitation, `readers: [everyone]`, `mdate: 1791448603689`. Plain ID lookup returns `InvitationExpiredError` after the call expires; the documented `expired=true` filter allows historical public metadata and does not bypass readership. No credentials are used. Fixed HTTPS destination owned by OpenReview, no redirects, no arbitrary navigation; the same reviewed-host DNS trust as the existing HTTP port applies.

## Mapping and limitations

Map exactly this invitation to `conference_cfp`, cycle 2027, track `workshop-proposals`, stable invitation-ID key. The human title/type/official URL are reviewed endpoint configuration; unknown invitation IDs or private readership fail visibly. The canonical link is the official call, original source is the exact public API query. This adapter supports this one reviewed call only; it does not guess metadata from arbitrary invitation names.

`duedate` is the API's submission cutoff (Unix milliseconds, exact UTC). It is distinct from the later `expdate` (API availability/grace), group event dates, and `cdate` (config activation, not assumed publication). Preserve cdate/mdate/expdate as bounded metadata, publication null, organization/location/work mode unknown unless explicit evidence is added in a reviewed future manifest. No paper-submission records or people are collected. The pure parser does not infer closed status from a wall clock; normal temporal eligibility interprets the deadline.

Manual comparison on 2026-10-29: API `duedate` is `1791637200000`, or 2026-10-10 13:00 UTC; `expdate` is 13:30 UTC, a separate 30-minute grace/availability boundary. The official call says October 9 at 23:59 AoE, corresponding to October 10 at 11:59 UTC, 61 minutes earlier. Preserve the API's labeled cutoff and provenance; do not silently edit it or claim official-page precision. This call is seasonally past. Future editions require a new reviewed manifest, never a guessed URL/year replacement. The rest of the product remains useful when this call is unavailable.

Manifest limits: exact endpoint above, one invitation / one request / one page, 65,536 decoded UTF-8 bytes, 15-second transport timeout, shared HTTP concurrency/redirect restrictions. Retryable failures are 408/429/5xx; numeric Retry-After is bounded by the existing 0–3,600-second worker policy. No in-adapter retry loop. Review broader rate/cooldown behavior before Phase 09 scheduling. Conditional ETag requests are used only when a fully committed compatible run provides both revision and validator; 304 reports no freshly parsed records.

Fixtures retain only metadata keys used by the mapper, identify omitted fields/synthetic mutations, include original endpoint/date/mdate/checksum and link the terms/attribution. No entire raw document is stored as provenance. A malformed/API-error document is distinct from a valid explicit empty invitation list. Bounded public-read smoke persists only to the isolated development target and cleans up; there is no production enablement.
